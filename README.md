# أزال سوفت

موقع تعريفي عربي متجاوب لشركة أزال سوفت للحلول الرقمية، يعرض خدمات الشركة ومشاريعها. الموقع موجود في مجلد `web` ويعمل كصفحات ثابتة دون الحاجة إلى Flutter أو خادم خلفي.

## التشغيل محلياً

```sh
python3 -m http.server 8000 --directory web
```

ثم افتح `http://localhost:8000`. يمكن نشر محتويات مجلد `web` على أي استضافة للمواقع الثابتة.

نموذج التواصل ينسخ تفاصيل الرسالة فقط ولا يرسلها تلقائياً، ويعرض الموقع أرقام الهاتف للتواصل المباشر. لإتاحة إرسال الرسائل تلقائياً، يجب ربط النموذج بخدمة استقبال رسائل.

## استمارة مسرّعة الأعمال وثبة

صفحة `web/apply.html` تعرض استمارة التقديم لمسرّعة الأعمال وثبة (الدفعة الثالثة) المقدمة من KoboToolbox مباشرة داخل الموقع:

- النموذج الأصلي: <https://ee.kobotoolbox.org/x/BDS6feIf>
- النسخة المدمجة المستخدمة داخل الصفحة: `https://ee.kobotoolbox.org/i/BDS6feIf`

يصل رابط الصفحة من قسم "المسرّعة" في الصفحة الرئيسية، ومن القائمة الرئيسية ومن بطاقة المشاريع الجديدة. يُرسل النموذج البيانات إلى خوادم KoboToolbox الرسمية، ولا يخزّن موقع أزال سوفت أي بيانات من الاستمارة.

عند حجب التضمين أو تعذّر تحميل الإطار، تعرض الصفحة بديلاً واضحاً برابط فتح الاستمارة في نافذة مستقلة. لضمان حفظ المسودة عند التعبئة داخل إطار مضمّن، يُفضّل استخدام زر الفتح في نافذة مستقلة.

يبقى مشروع Flutter الأصلي في المستودع منفصلاً عن الموقع الثابت.

## النشر على Firebase Hosting

الموقع صفحات ثابتة جاهزة للنشر مباشرة من مجلد `web`، ولا يحتاج إلى تشغيل `flutter build web`. ملف `firebase.json` يحدد هذا المجلد كمصدر للنشر. تحقّق من استخدام مشروع Firebase مخصص للموقع قبل النشر، لأن النشر على موقع مستعمل سيستبدل محتواه الحالي.

بعد تثبيت Firebase CLI وتسجيل الدخول إليه على جهازك، نفّذ:

```sh
firebase deploy --only hosting --project PROJECT_ID
```

استبدل `PROJECT_ID` بمعرّف مشروع Firebase المقصود. إذا كان المشروع يحتوي على عدة مواقع استضافة، يجب إعداد هدف استضافة للموقع المطلوب بدلاً من النشر على الموقع الافتراضي.
